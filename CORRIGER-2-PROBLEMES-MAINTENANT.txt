🔍 DIAGNOSTIC:

Le problème vient des données dans Supabase:
- Les articles ont des slugs avec timestamps
- Au lieu d'utiliser les slugs propres des fichiers JSON locaux

VÉRIFICATION DANS SUPABASE:

Exécute cette requête dans SQL Editor pour vérifier:

SELECT id, slug, title, created_at
FROM blog_posts
ORDER BY created_at DESC
LIMIT 10;

Tu vas probablement voir:
  slug = "assurance-taxi-melun-1761106394869-1761132334521" ❌

Au lieu de:
  slug = "assurance-taxi-2024" ✅

┌─────────────────────────────────────────────────────────────────────────┐
│  SOLUTION 2: Corriger les Slugs des Articles                           │
└─────────────────────────────────────────────────────────────────────────┘

Option A: Nettoyer les slugs automatiquement (RECOMMANDÉ)

Exécute cette requête dans SQL Editor:

```sql
-- Nettoyer les slugs en enlevant les timestamps
UPDATE blog_posts
SET slug = REGEXP_REPLACE(slug, '-[0-9]{13,}-[0-9]{13,}$', '')
WHERE slug ~ '-[0-9]{13,}-[0-9]{13,}$';

-- Vérifier le résultat
SELECT slug, title FROM blog_posts ORDER BY created_at DESC LIMIT 10;
```

Cela va transformer:
  "assurance-taxi-melun-1761106394869-1761132334521"
    ↓
  "assurance-taxi-melun"

Option B: Supprimer et réinsérer les articles

Si Option A ne fonctionne pas, exécute:

```sql
-- Supprimer tous les articles avec slugs incorrects
DELETE FROM blog_posts WHERE slug ~ '-[0-9]{13,}';

-- Les articles seront rechargés depuis les fichiers JSON locaux
-- lors de la prochaine visite de la page /blog
```
